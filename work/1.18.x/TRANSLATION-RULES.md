# Wesnoth 1.18.x Translation Rules

이 문서는 1.18.x 한국어 PO 작업의 번역·용어·고유명사 표기 기준을
통합한 기준 문서다. `PROJECT-AI.md`는 프로젝트 전체의 역할과 작업
흐름을, 이 문서는 실제 번역 판단 기준을 담당한다. `glossary.tsv`는
이 문서의 규칙에 따라 승인된 개별 표준값과 예외를 기록한다.

## 1. 우선순위

번역 판단은 다음 순서로 한다.

1. 현재 영어 원문과 실제 게임 문맥
2. 이미 정착된 최신 한국어 번역
3. 프로젝트 용어집의 승인된 표준값과 예외
4. 게임 내 다른 PO의 동일·유사 용례
5. 일본어·중국어 PO와 과거 참고 자료

용어집은 불변의 진실이 아니다. 실제 원문이나 문맥과 충돌하면 충돌
사례를 감사 리포트에 기록하고 용어집과 영향받는 PO를 함께 재검토한다.

## 2. 고유명사 표기

- 인명·지명·내부 세력명·고유 유닛명은 한국어 음차를 우선한다.
- 필요한 내부 고유명사는 `한글(원문)`으로 병기한다.
- 복합 표현에서는 고유명사 부분만 병기한다. 직함·수식어·일반명사는
  괄호에 넣지 않는다.
  - `Minion of Tairach` → `타이라크(Tairach)의 졸개`
  - `Lady Dionli` → `디온리(Dionli) 부인`
  - `River Longlier` → `롱리어(Longlier) 강`
- 첫 등장 여부만으로 병기하지 않는다. PO 전체 용례에서 동일한 표기를
  유지한다.
- `Discord`, `Steam`, `IRC`, 도구명·프로토콜·외부 식별자는 내부
  고유명사와 구분해 원문을 유지할 수 있다.
- 원문이 영어가 아닌 것처럼 보이거나 출처 언어가 불명확해도 의미를
  임의로 번역하지 않는다. 고유명사라면 우선 음차하고 원문을 병기한다.
  - `Wose` → `워즈(Wose)`, 의미역 `나무 인간`으로 바꾸지 않는다.
  - `Khrakrahs` → `크흐라크라흐스(Khrakrahs)`.
- `data/core/macros/names.cfg`의 이름 생성기 문법이나
  `random_names.lua`의 목록에서 런타임에 조합·선택되는 유닛 이름은 PO에
  독립된 `msgid`로 존재하지 않을 수 있다. 예를 들어 게임에 `Losel`이
  표시되어도 원문 데이터에 그 문자열이 없으면 번역 누락으로 보지 않는다.
  생성기 토큰과 문법은 임의로 음차·번역하지 않고 원문 구조를 유지한다.

### Defense와 Defense Cap

- `Defense`는 지형·유닛 수치 UI에서 백분율로 표시되므로 `방어율`로
  번역한다. 일반적인 방어 행위나 서술 문맥에서는 `방어`로 번역할 수
  있지만, 수치 표의 라벨에는 사용하지 않는다.
- `Defense Cap`은 방어율에 적용되는 별도 상한 규칙이다. 피해 저항이나
  추가 방어 보너스를 뜻하지 않으며, 혼합 지형에서 특정 기본 지형이
  포함될 때 해당 유닛의 방어율이 그 기본 지형의 방어율보다 좋아지지
  못하게 한다. 설명 문맥의 정확한 의미는 `방어율 상한`으로 기록한다.
- `Defense Cap`은 `Defense`와 구분되는 지형별 백분율의 상한이므로
  `방어율 상한`으로 번역한다.

## 2.1 병기 판정

병기는 “영어가 남아 있으면 괄호를 붙이는” 규칙이 아니다. 원문과
한국어를 토큰 단위로 비교해, 한국어가 실제로 음차한 내부 고유명사
부분에만 원문을 붙인다.

### 병기 대상

다음은 기본적으로 `한글(원문)` 형식으로 병기한다.

- 인명: `말린 케샤르(Malin Keshar)`
- 지명: `에스트마르크(Estmark) 언덕`
- 내부 세력·진영명: `퀴노스(Quenoth) 엘프들`
- 고유 유닛·종족명: `워즈(Wose)`, `웜(Wyrm)`
- 본문에 새로 등장한 내부 고유명사: 짧은 UI든 장문 서술이든 같은 기준

한국어 표기가 이미 정착되어 있어도 내부 고유명사이고 원문 대응을
명확히 해야 한다면 병기한다. 병기 여부를 첫 등장 위치에 따라 다르게
하지 않는다.

### 병기하지 않는 대상

- 일반명사: `Masked Dwarf` → `가면 쓴 드워프`
- 직함·호칭: `Lady Dionli` → `디온리(Dionli) 부인`
- 지형 일반명사: `River Longlier` → `롱리어(Longlier) 강`
- 외부 브랜드·프로토콜·도구명: `Discord`, `Steam`, `IRC`, `wmllint`
- 한국어로 의미를 번역한 일반 표현: 원문을 괄호에 반복하지 않는다.

### 복합 표현 분리

전체 영어 키를 괄호에 넣지 않고, 고유명사 토큰만 병기한다.

| 원문 | 올바른 표기 | 잘못된 표기 |
|---|---|---|
| `Minion of Tairach` | `타이라크(Tairach)의 졸개` | `타이라크의 졸개(Minion of Tairach)` |
| `Bones of Malin Keshar` | `말린 케샤르(Malin Keshar)의 뼈` | `말린 케샤르의 뼈(Bones of Malin Keshar)` |
| `Lady Dionli` | `디온리(Dionli) 부인` | `부인 디온리(Dionli)` |
| `Ford of Alyas` | `알리아스(Alyas) 여울` | `알리아스(Alyas)의 여울` |
| `North Knalga` | `북부 크날가(Knalga)` | `북부(North) 크날가(Knalga)` |

직함·수식어·소유격 조사·지형 일반명사는 고유명사 괄호 안에 넣지 않는다.
복합 인명은 특별한 근거가 없으면 구성요소별로 따로 병기하지 않고
전체 이름을 한 번 병기한다.

### 반복·중첩 방지

- 같은 `source_term`은 모든 활성 PO에서 동일한 병기 표기를 사용한다.
- 이미 `한글(English)`인 이름에 다시 `(English)`를 붙이지 않는다.
- `한글(English)(English)`처럼 중첩하지 않는다.
- 한 문장 안에서 전체 이름을 병기한 뒤 구성요소를 다시 병기하지 않는다.
- obsolete 항목도 삭제하지 않으며, 활성 항목과 동일한 번역·복수형·병기
  규칙으로 감사하고 표준화한다. 단, 활성 완료 통계에는 포함하지 않는다.
- 용어집의 `category`만 보고 병기하지 않는다. 실제 영어 원문과 한국어
  대응을 직접 확인한다.

### 문맥 키와 병기

`female^`, `male^`, `race^`, `team_name^`, `wc_variation^` 등의 gettext
접두사는 병기 대상이 아니다. 접두사는 `source_term`에만 보존하고,
표시 문자열에 해당하는 `^` 뒤의 부분만 번역·병기한다.

- `race^Wose` → `워즈(Wose)`
- `team_name^Quenoth Elves` → `퀴노스(Quenoth) 엘프들`
- `female^Elvish Archer` → `엘프 궁수`

`female^` 자체를 `여성^`으로 표시하거나, 문맥 키까지 괄호에 넣지 않는다.

### 병기 결정 순서

1. 원문에서 고유명사 토큰과 일반명사·직함·지형명을 분리한다.
2. 한국어가 음차인지 의미역인지 확인한다.
3. 음차한 고유명사 토큰만 `한글(원문)`으로 만든다.
4. 기존 용어집과 전체 PO에 같은 표기가 있는지 확인한다.
5. 긴 문장과 obsolete 항목까지 중첩·누락을 검사한다.
6. 근거가 불충분하면 자동 병기하지 않고 후보로 기록한다.

### 의미역 가능한 고유 지명

영어 원문이 `Clearwater`, `Blue Water`, `Silverhead`처럼 일반 영어
단어로 구성되어 있어 자연스럽게 의미역할 수 있더라도, 게임 세계 안에서
특정 도시·항구·호수·지역의 이름으로 사용되면 고유 지명으로 취급한다.
이 경우 의미를 살린 한국어 번역 뒤에 원문을 병기한다.

- `Clearwater Port` → `맑은물(Clearwater) 항구`
- `Clearwater Lake` → `맑은물(Clearwater) 호수`
- `Blue Water Province` → `푸른물(Blue Water) 주`
- `Silverhead Crossing` → `실버헤드(Silverhead) 건널목`

이 규칙은 “영어처럼 보이는 이름만 음차한다”는 규칙의 예외가 아니다.
한국어 의미역이 자연스럽고 기존 번역에 정착되어 있어도, 원문 식별
정보를 보존하기 위해 병기한다. 단, `clear water`가 실제 지명으로
사용되지 않은 일반적인 물의 묘사라면 병기하지 않는다.

지명 전체를 괄호에 넣지 않고, 의미역한 고유 지명 부분만 병기한다.
따라서 `맑은물(Clearwater) 항구`는 올바르지만
`맑은물 항구(Clearwater Port)`는 사용하지 않는다.

### 의역된 고유명사

고유명사의 뜻이나 이미지가 한국어에서 더 잘 전달되도록 의역하더라도,
그 이름이 게임 세계 안에서 특정 인물·세력·지역·종족·유닛을 가리키는
고유명사라면 원문을 병기한다. 음차 여부가 아니라 “고유명사 식별 정보가
번역 과정에서 사라졌는가”를 기준으로 판단한다.

- `Clearwater` → `맑은물(Clearwater)`
- `Blackwater` → `검은물(Blackwater)`
- `Slowhand` → `느린손(Slowhand)`
- `Wesfolk` → `서부인(Wesfolk)`

고유명사의 일부만 의미역한 경우에도 해당 부분과 원문 대응을 명확히
한다. 일반명사·직함·지형 일반명사는 병기하지 않는다.

다음은 이 규칙의 대상이 아니다.

- 실제 고유명사가 아닌 일반 표현: `clear water` → `맑은 물`
- 작품명·캠페인 제목을 한국어 제목으로 현지화한 경우: 제목의 자연스러움과
  기존 정착 표기를 우선하며, 개별 제목마다 병기 여부를 별도로 판단한다.
- 고유명사성이 확인되지 않은 후보: 근거를 감사 리포트에 남기고 확정 전에는
  자동으로 병기하지 않는다.

## 3. 음차·발음 규칙

### 3.1 출처 언어 판정

영어 철자처럼 보인다는 이유만으로 영어 발음을 적용하지 않는다. 먼저
다음 단서를 확인한다.

- 공식 게임 자료, 음성, 개발 문서 또는 기존 한국어 표기
- 원문 이름의 철자·기호·어미와 같은 세계관 내 유사 이름
- 이름이 쓰인 종족·지역·문화권의 설정
- 영어·프랑스어·독일어·라틴어·그리스어 등으로 보이는 철자 특징
- 일본어·중국어 PO의 표기

출처 언어를 확정할 수 없으면 특정 언어의 발음 규칙을 과도하게
추정하지 말고, 프로젝트 안에서 반복되는 음가와 기존 한국어 표기를
우선해 일관된 음차를 만든다.

### 3.2 음차 우선순위

1. 이미 공식적·프로젝트적으로 정착된 한국어 표기
2. 확인 가능한 원어 발음
3. 원어를 알 수 없을 때의 철자와 세계관 내 유사 이름
4. 일본어·중국어 표기에서 얻는 보조 힌트

일본어의 영어 보존이나 중국어의 한자음은 한국어 발음의 정답이 아니다.
참고 locale이 서로 다르면 한국어 음차를 새로 판단하고 근거를 남긴다.

### 3.3 한국어 음차 작성

- 철자를 글자 단위로 기계 치환하지 않는다.
- 한국어 독자가 실제로 읽을 수 있는 음절로 나눈다.
- 한국어 음차만으로 원문을 복원하기 어려운 이름은 반드시
  `한글(원문)`으로 병기한다.
- 하이픈·아포스트로피·대문자 경계는 원문 병기에서 보존한다.
  한국어 표기에서 하이픈을 유지할지 여부는 정착 표기와 발음의
  자연스러움을 함께 본다.
- `th`, `ch`, `gh`, `-tion`, 묵음 문자처럼 철자와 발음이 어긋날 수
  있는 부분은 단어 전체 발음과 유사 이름을 확인한다. 한 글자마다
  동일한 한국어 음가를 강제하지 않는다.
- 이름 안에 일반 영어 단어가 포함되어도 전체가 고유명사이면 음차하고,
  실제로 일반명사 역할을 하는 부분만 번역한다.
- 출처 언어가 확실하지 않은 이름을 한국어 의미로 의역하지 않는다.
  의미를 번역해야 하는 이름은 설정·게임 UI·기존 공식 번역에서
  의미역이 확인된 경우로 제한한다.

### 3.4 발음이 불확실한 경우

다음 중 하나라도 해당하면 즉시 확정하지 않는다.

- 동일 이름의 발음 후보가 둘 이상이고 문맥상 구별 근거가 없는 경우
- 원문이 영어인지 고유 창작어인지 확인되지 않는 경우
- 참고 locale들이 서로 다른 음가를 암시하는 경우
- 기존 한국어 표기가 여러 형태로 충돌하는 경우

이때는 다음을 수행한다.

1. 현재 표기는 가장 보수적인 음차와 원문 병기로 둔다.
2. `glossary.tsv`의 `notes`에 불확실성과 판단 근거를 적는다.
3. 감사 리포트에 후보 표기와 확인이 필요한 자료를 기록한다.
4. 발음이 확인되기 전까지 PO 전체에서 임의로 다른 표기를 섞지 않는다.

### 3.5 대표 사례

| 원문 | 표준 표기 | 판단 |
|---|---|---|
| `Arvith` | `아르비쓰(Arvith)` | 정착 한국어와 `th` 발음을 반영 |
| `Mal Tath` | `말 타쓰(Mal Tath)` | 복합 인명 전체를 한 번 병기 |
| `Verloth` | `베를로쓰(Verloth)` | 철자식 `스`가 아닌 발음 기준 |
| `Wose` | `워즈(Wose)` | 의미역하지 않는 창작 종족명 |
| `Saurian` | `사우리안` | 일반 `Lizard`와 구분하는 고유 종족명 |
| `Wyrm` | `웜(Wyrm)` 또는 문맥상 `뱀룡` | 멸칭 문맥에서는 `도마뱀` 예외 가능 |

## 4. 종족·생물명

- `Elf/Elves` → `엘프/엘프들`
- `Dwarf/Dwarves/Dwarvish` → `드워프/드워프들/드워프의` 또는
  문맥에 맞는 `드워프제` 형태
- `Dwarf`는 판타지 세계의 고유 종족명이므로 일반어 `난쟁이`로 번역하지
  않는다. 종족명·유닛명·설명문 모두 같은 기준을 적용한다.
- `faerie` → `요정`
- `Saurian/Saurians` → `사우리안/사우리안들`
- `Wose/Woses` → `워즈(Wose)/워즈들(Woses)`
- 명시적 영어 복수형은 한국어도 `들`로 표시한다. `족`을 복수형
  표지로 사용하지 않는다.
- `Lizard/lizard`는 일반 동물·일반 생물명 문맥의 `도마뱀`으로 두고
  `Saurian`과 섞지 않는다.
- `Wyrm`은 일괄 치환하지 않는다.
  - 중립적 고유 생물명·유닛명: `웜(Wyrm)` 또는 `웜`
  - 설명문에서 형태를 풀어 쓰는 중립 문맥: `뱀룡`
  - 상대를 낮춰 부르는 대화의 멸칭: 문맥상 `도마뱀/도마뱀들`
  - `Wyrms of Khrakrahs`: `크흐라크라흐스(Khrakrahs) 뱀룡`

## 5. 게임 용어와 UI

- `heal/healing` → `회복`
- `cure/cures` → `치료`
- `Always rest heals` → `상시 휴식 회복`
- `Frozen terrain` → `얼음 지형`
- 상태값과 지형명이 같은 원문을 공유해도 문맥을 확인한 뒤 번역한다.
- `Close` → `닫기`
- UI의 `Exit/Leave` → `나가기`
- 프로그램·게임 종료의 `Quit` → `종료`
- 목적지가 명시된 종료 명령은 목적지를 보존한다.
  - `Quit to Menu` → `메뉴로 나가기`
  - `Quit to Desktop` → `바탕 화면으로 나가기`
- `Quit` 단독은 게임·프로그램 자체를 닫는 동작이므로 `종료`로 두고,
  `Quit to Menu/Desktop`은 게임을 완전히 닫지 않고 해당 화면·환경으로
  이동하는 동작이므로 `나가기`로 구분한다.
- `data/themes/default.cfg`의 우측 패널 `[label]: id=label-*` 항목은
  공간 제약 예외를 적용한다.
  - `HP` → `HP`
  - `XP` → `XP`
  - `MP` → `MP`
  - `def` → `def`
- `statuspanel^lvl`은 우측 패널의 공간 제약으로 `lvl`을 유지한다.
- 위 축약은 해당 우측 패널 라벨에만 적용한다. 일반 문장·도움말·다른
  UI에서는 `체력`, `경험치`, `이동력`, `방어력` 등의 문맥별 표준값을
  유지한다.

`level`은 문맥에 따라 구분한다.

- 유닛 성장 단계·유닛 레벨: `레벨`
- 난이도·로그·일반적인 정도: `수준`
- `statuspanel^lvl`: 우측 패널에서는 `lvl`

`defence/defense`는 기본적으로 `방어`, `evasion`은 `회피`로 번역한다.
원문 용어가 `defence/defense`인지 `evasion`인지 먼저 확인하고 적용한다.
다만 게임 수치의 표시 방식에 따라 다음처럼 자연스러운 파생 표현을 사용할
수 있다.

번역 노트: 게임 설정상 `defence/defense` 수치는 공격이 빗나갈 확률,
즉 한국어 의미로는 회피에 가깝다. 그러나 원문 용어의 구분을 보존하기
위해 `defence/defense`를 `회피`로 바꾸지 않고 `방어` 계열로 번역하며,
원문이 `evasion`인 경우에만 `회피` 계열을 사용한다.

- `defence/defense`의 일반 개념·행위: `방어`
- `defence/defense`의 유닛·지형 수치: `방어력`, `방어율`, `방어도`
- `evasion`의 회피 수치·능력: `회피`, `회피율`

게임 규칙상 회피처럼 보이는 수치라도 원문이 `defence/defense`이면
임의로 `회피`로 바꾸지 않는다.

## 6. 문맥·구조 보존

- 장문 서술도 검수 대상에서 제외하지 않는다. 의미·문체·화자·조사·
  띄어쓰기를 실제 문맥에서 확인한다.
- 원문에 없는 정보를 추가하지 않는다.
- 태그, placeholder, 실제 `\n`, 복수형 필드, manpage 표식과 명령어는
  보존한다.
- gettext 문맥 접두사 `female^`, `male^`, `race^` 등은 번역문에
  표시하지 않는다.
- 같은 표기라도 `msgctxt`나 화면 역할이 다르면 단일 번역으로
  강제하지 않는다.

## 7. 용어집 기록

`glossary.tsv`는 다음을 기록한다.

- `source_term`: 실제 원문 키
- `standard_korean`: 승인된 한국어 표준값
- `reference_japanese`, `reference_chinese`: 보조 참고값
- `category`: 의미 분류
- `forbidden_terms`: 채택하지 않는 과거 표현·오역
- `notes`: 발음 불확실성, 문맥 예외, 병기 근거

긴 대사와 장문 설명 전체는 용어집에 넣지 않는다. 반복 가능한 단어,
짧은 고정 UI 문구, 고유명사와 예외만 기록한다.

## 8. 검수 절차

1. 현재 PO의 원문·문맥·참고 locale·최신 한국어 자료를 확인한다.
2. 검수자는 후보와 근거를 감사 리포트에 기록하고 PO를 수정하지 않는다.
3. 승인된 항목만 수정자가 PO·용어집에 반영한다.
4. 같은 원문이 있는 전체 PO에서 영향 범위를 확인한다.
5. `untranslated=0`, `fuzzy=0`, 구조 감사, 용어집 감사, `msgfmt`를
   실행한다.
6. 파일별 변경·보류·용어집 영향·검증 결과를 리포트로 남긴다.

## 9. 참고 자료 사용

참고 자료는 다음처럼 사용한다.

- `References/20250322_wesnoth_한국어번역/`: 최신 한국어 참고 자료
- `po/1.18.x/ja/`: 일본어 표현과 원문 보존 여부 비교
- `po/1.18.x/zh_CN/`: 중국어 의미역과 고유명사 비교
- `po/1.18.x/en_GB/`: 영어 키와 원문 구조 확인
- `References/wesnothko/`: 과거 번역 결정과 세계관 문맥 확인

참고 자료를 기계적으로 복사하지 않는다. 현재 원문·문맥·태그·placeholder·
자연스러운 한국어와 충돌하면 현재 원문을 우선하고 조정 근거를 기록한다.
일본어가 영어를 보존하거나 중국어가 한자로 의미역했다고 해서 한국어
표기를 자동 결정하지 않는다.

## 10. 문맥 키와 성별 표기

`source_term`의 `^`는 gettext 문맥 또는 Wesnoth 표시 문맥일 수 있다.
문맥 키와 화면 표시 문자열을 분리해 처리한다.

- `female^`, `male^`, `race^`의 접두사는 번역문에 표시하지 않는다.
- `feature^`, `controller^`, `team_name^` 등의 접두사도 표시 문자열이
  아닌 식별자이면 번역하지 않는다.
- 같은 표시 문자열이라도 문맥 키가 다르면 용어집 항목을 합치지 않는다.
- 긴 본문 속 `^Uf`, `^Tf`, `^Efs` 같은 WML·지형 코드는 일반 문맥
  접두사로 오인하지 않는다.

성별은 `female^`만으로 번역하지 않는다.

- `Archer`, `Mage`, `Guard`처럼 한국어에서 성별 중립인 직업명은 기본형과
  여성형을 동일하게 둔다.
- `Princess`, `Queen`, `Lady`, `Priestess`, `Sorceress`, `Baroness`,
  `Watchwoman`처럼 단어 자체에 성별 의미가 있으면 자연스러운 한국어
  대응어를 검토한다.
- `Watchwoman`처럼 한국어에서 성별을 표시하지 않는 편이 자연스러운
  단어는 `야경꾼`으로 둔다.
- `Mage=마법사`, `Sorcerer=마법사`, `Wizard=마도사`처럼 영어 단어가
  다르더라도 프로젝트에서 확정한 한국어 체계를 우선한다.

## 11. 종족·세력·복수형

영어 원문의 문법적 수와 화면 역할을 분리한다.

- 단수 종족명: `Elf=엘프`, `Saurian=사우리안`
- 명시적 복수 종족명: `Elves=엘프들`, `Saurians=사우리안들`
- 명시적 세력명 복수형도 원문이 복수이면 `들`을 사용한다.
- `족`은 영어 복수형을 나타내는 표지로 사용하지 않는다.
- 일반 문장에서 종족 개념을 설명하기 위해 `족`이 필요하면 예외 근거를
  문맥별로 확인한다.
- `Saurian`과 `Lizard`를 같은 번역으로 합치지 않는다.
- 일반 `Lizard`는 `도마뱀`, 고유 종족 `Saurian`은 `사우리안`으로 둔다.

`faction`과 `race_name`은 자동으로 같은 의미라고 보지 않는다. 캠페인
세력명, 멀티플레이 진영명, 도움말의 종족 목록을 각각 실제 화면 역할과
원문 수에 따라 확인한다.

## 12. UI·게임 규칙 용어

짧은 UI 용어는 자연스러운 동작 표현을 우선한다.

| 원문 | 표준 | 구분 |
|---|---|---|
| `Close` | `닫기` | 현재 창·대화창 닫기 |
| `Exit` | `나가기` | UI·방·화면에서 나가기 |
| `Leave` | `나가기` | UI에서 떠나기 |
| `Quit` | `종료` | 게임·프로그램 종료 |
| `heal/healing` | `회복` | HP 회복 |
| `cure/cures` | `치료` | 독·상태 이상 제거 |
| `Always rest heals` | `상시 휴식 회복` | 휴식 시 적용되는 특성 |
| `Frozen terrain` | `얼음 지형` | 눈·얼음으로 덮인 지형 |

같은 영어 단어가 상태값·지형명·메뉴 항목으로 재사용되면 하나의 한국어
값으로 기계 통일하지 않는다. 예를 들어 `Frozen`은 지형 문맥에서
`얼음 지형`으로 처리하고, 상태값이 별도로 확인되면 그 문맥을 다시
검토한다.

응답과 상태를 구분한다.

- 일반 응답 `yes/no` → `예/아니오`
- 존재 여부·활성 상태의 `yes/no` → 문맥에 따라 `있음/없음` 검토
- `Music`은 크레딧의 `[about]`에서는 `음악 담당`, 설정 열에서는
  `음악`처럼 화면 역할을 확인한다.

도구명과 명령어는 의미를 확장하지 않는다.

- `wmllint`, `wmlindent`, `wmlscope`는 원문 유지
- `wmllint mode` → `wmllint 모드`
- `Run wmlindent`처럼 동작이 결합되면 짧은 UI 문장으로 번역

## 13. 문장·문체·띄어쓰기

- 장문 서술·세계관 설명도 검수 대상이다.
- 의미가 맞더라도 명백한 오탈자, 조사 오류, 띄어쓰기 오류, 문장 구조
  오류는 수정한다.
- 단순한 문체 취향, 방언, 의도적인 비문, 화자의 말투는 의미 손실이
  없으면 보수적으로 유지한다.
- 대사에서는 화자의 성격·높임말·반말·명령형을 앞뒤 문맥과 맞춘다.
- 화자 말투는 화자와 상대의 관계를 먼저 판정한다. 가족·형제·친구·
  동료·상하관계·초면 여부에 따라 호칭과 높임 정도를 정하고, 영어의
  중립적인 `you`를 한국어 `당신`으로 기계적으로 옮기지 않는다.
- 관계가 원문에서 확정되는 경우에는 한국어 호칭을 관계에 맞게 복원한다.
  예를 들어 형제 사이의 대화에서는 `너`, `오빠`, `누나` 등을 검토하고,
  왕에게는 `전하`, 스승·상관에게는 `선생님`, `주군`, `자네` 등의
  호칭을 문맥에 맞게 사용한다.
- 방언·말버릇·의도적인 문법 파괴는 캐릭터성의 일부일 수 있으므로
  표준어로 평탄화하지 않는다. 다만 그 말투 안에서 의미가 뒤집히거나
  명백한 오탈자가 있으면 수정한다.
- 동일 화자의 말투가 장면 전환이나 관계 변화 없이 갑자기 바뀌는 경우만
  후보로 기록한다. 종결어미의 모든 변이를 자동으로 하나로 통일하지 않는다.
- 설명문에서는 같은 대상을 가리키는 명칭과 수를 일관되게 유지한다.
- 한국어 문장을 자연스럽게 만들기 위해 원문에 없는 사실을 추가하거나
  설정을 보충하지 않는다.
- `안드는네요`처럼 명확한 오타는 문맥을 확인해 `들지 않는군요`,
  `안 드는데요` 등 의미를 보존하는 자연스러운 형태로 수정한다.

## 14. PO 구조 보존

번역 품질과 별개로 다음 구조는 반드시 원문과 대조한다.

- 실제 개행 문자 `\n`
- `<i>`, `<b>`, `<span>`, `<ref>` 등의 태그와 속성
- `%s`, `%d`, `$unit.name`, `$gold_cost` 등의 placeholder
- 복수형 `msgstr[n]`
- manpage roff 표식
- WML 코드, 지형 코드, 명령어, 경로

PO에서 여러 줄로 나뉜 따옴표 문자열은 파일 가독성을 위한 분할일 수
있다. 물리적인 줄 수를 맞추는 것이 아니라 gettext가 해석하는 실제
문자열·개행·태그·placeholder를 보존한다.

원문 태그나 placeholder가 불균형해 보이면 번역자가 임의로 고치지 않는다.
원문 오류 가능성을 감사 리포트에 기록하고, 구조 감사 결과와 함께
검토한다.

## 15. 용어집 스키마와 기록 원칙

`glossary.tsv`는 탭으로 구분된 8열 구조를 유지한다.

| 열 | 의미 |
|---|---|
| `source_term` | 비교 대상 원문 키 |
| `standard_korean` | 승인된 한국어 표준값 |
| `reference_japanese` | 일본어 참고값 |
| `reference_chinese` | 중국어 참고값 |
| `category` | 의미 분류 |
| `forbidden_terms` | 채택하지 않는 대안·과거 표현 |
| `notes` | 예외·발음·문맥·병기 근거 |

실제 파일의 헤더·열 수는 저장소 테스트가 정하는 기준을 따른다. 용어집
항목은 반복 가능한 짧은 표현을 위한 것이며 다음은 등록하지 않는다.

- 긴 대사·서사문 전체
- 한 번만 등장하는 일반 문장
- 숫자만 있는 값
- 기호만 있는 값
- 문맥을 모르면 의미를 정할 수 없는 후보

`forbidden_terms`는 표준값과 같은 표현을 넣지 않는다. 과거 오역을
삭제하지 않고 보존할 필요가 있을 때만 기록한다. `notes`에는 출처
나열보다 실제 결정 이유와 예외를 기록한다.

## 16. 용어집과 PO 충돌 처리

용어집 값과 PO가 다르다고 즉시 PO 전체를 덮어쓰지 않는다.

1. 정확한 `msgctxt`, `msgid`, 화면 역할과 현재 번역을 확인한다.
2. 용어집 값이 문맥을 과도하게 일반화했는지 확인한다.
3. 충돌을 감사 리포트에 `수정`, `문제 없음`, `계속 보류`로 기록한다.
4. 표준값을 바꾸면 `standard_korean`, `forbidden_terms`, `notes`와
   영향받는 PO를 같은 사이클에서 갱신한다.
5. 자동 전체 치환 대신 승인된 영향 범위만 수정한다.
6. 같은 도구를 반복 실행해도 결과가 다시 바뀌지 않는지 확인한다.

## 17. 감사 명령과 완료 조건

## 18. 언어 목록 메타데이터

`work/<버전>/ko_KR.cfg`의 언어 목록 메타데이터는 다음처럼 관리한다.

- `name`: `한국어 (<작업버전>-<최종수정일>)` 형식으로 현재 작업 세대를 표시한다.
- `sort_name`: 정렬용 고정값인 `Hangugeo`를 유지한다. 작업 버전·날짜를 넣지 않는다.
- `percent`: 완료된 배포 기준에서는 `100`으로 유지한다.

`tools/mark_korean_locale.sh`와 PowerShell 대응 스크립트도 `name`만 갱신하며,
`sort_name`은 변경하지 않는다.

파일별 완료는 다음 조건을 모두 만족해야 한다.

```sh
python3 -m unittest discover -s tests -v
python3 tools/audit_po_structure.py
python3 tools/audit_glossary.py
python3 tools/audit_po_completion.py work/1.18.x/ko
find work/1.18.x/ko -name '*.po' -print0 |
  xargs -0 -n1 msgfmt --check --check-format --output-file=/dev/null
```

정상 기준은 다음과 같다.

- 활성 `untranslated=0`
- 활성 `fuzzy=0`
- `markup_mismatches=0`
- `placeholder_mismatches=0`
- `newline_mismatches=0`
- 용어집 `errors=0`, `warnings=0`
- 테스트와 `msgfmt` 종료 코드 성공

자동 감사 통과는 의미 검수 완료를 뜻하지 않는다. 반대로 문장 검수가
끝났더라도 구조·용어집·완료 감사가 실패하면 파일 완료로 보고하지 않는다.
